# ☁️ 플랜두씨 (PlanDoSee) — ALEPH T07

**계획부터 실행, 돌아보기까지 기록하는 나만의 웹 다이어리**

플랜두씨는 계획을 세우고, 실제로 수행한 일을 기록하며, 그 결과를 돌아볼 수 있는 웹 다이어리입니다.

기존 ALEPH T06 PlanDoSee를 기반으로 제작하였으며, T07에서는 **회원가입·로그인 기능과 사용자별 데이터 분리 기능**을 추가했습니다.

각 사용자는 자신의 계정으로 로그인하여 계획과 할 일, 실행 기록, 돌아보기 내용을 관리할 수 있습니다.

## ✨ 주요 기능

### 1. 회원가입 및 로그인 (AUTH)

- 이메일과 비밀번호를 이용한 회원가입
- 기존 계정 로그인 및 로그아웃
- 로그인 상태 확인
- 로그인한 사용자에게만 다이어리 화면 제공
- 인증되지 않은 사용자의 데이터 API 접근 제한
- 사용자별 계획 및 기록 관리

로그인 과정은 Vercel 서버 API를 통해 처리하며, Supabase Auth를 사용하여 사용자를 인증합니다.

인증에 필요한 세션 정보는 서버에서 설정하는 HttpOnly 쿠키를 통해 관리합니다.

### 2. 계획 관리 (PLAN)

- 계획 제목, 시작 날짜, 종료 날짜 입력
- 계획별 성공 기준과 예상 시간 설정
- 계획 생성 및 수정
- 선택한 날짜에 해당하는 계획 표시
- 계획 수정 전후 내용을 수정 이력으로 보관
- 수정 날짜 및 시각 확인
- 각 계획에 연결된 할 일 미리보기 제공

계획의 내용을 수정하면 변경 전후 정보가 수정 이력에 저장됩니다.

### 3. 할 일 관리 (DO)

- 계획에 연결되는 할 일 추가 및 수정
- 시작 날짜와 마감일 지정
- 예상 시간을 시간과 분으로 입력
- 우선순위(높음, 보통, 낮음)와 태그 설정
- 제목 검색 및 다양한 필터 기능
- 우선순위 및 날짜 등에 따른 정렬
- 할 일 완료 체크

할 일은 시작 날짜부터 마감일까지 선택한 날짜의 목록에 표시됩니다.

완료 상태는 날짜별 실행 기록을 기준으로 확인하므로, 같은 할 일도 다른 날짜에 다시 완료할 수 있습니다.

### 4. 실행 기록 관리

- 실행한 할 일 선택
- 시작 날짜·시각 및 종료 날짜·시각 입력
- 실제 소요 시간 자동 계산
- 막힌 이유 또는 메모 기록
- 할 일 완료 시 실행 기록 함께 저장
- 저장된 실행 기록 조회 및 수정
- 동일한 날짜의 중복 완료 기록 검사

실행 기록은 계획 및 할 일 정보와 연결되며, 실제 수행한 활동을 별도로 관리합니다.

### 5. 돌아보기 (SEE)

계획과 할 일, 실행 기록을 바탕으로 수행 결과를 확인할 수 있습니다.

**주요 집계 항목**
- 계획에 연결된 할 일 수
- 완료한 일 수
- 지연된 일 수
- 막힌 일 수
- 예상 시간과 실제 시간
- 예상 시간 대비 실제 시간의 차이

계획과 기간을 선택하여 기록을 확인하고, 돌아보기 메모를 작성하여 다음 계획에 개선 사항을 연결할 수 있습니다.

### 6. 전체 기록 내보내기

계획, 할 일, 실행 기록, 돌아보기를 하나의 JSON 파일로 내보낼 수 있습니다.

계획 수정 이력도 함께 포함되어 기록을 별도로 보관할 수 있습니다.

## 🔐 인증 및 사용자별 데이터 분리

T07에서는 기존 T06의 공통 데이터 저장 방식에서 사용자별 데이터 저장 방식으로 변경했습니다.

**인증 및 데이터 처리 흐름**

1. 사용자가 이메일과 비밀번호로 회원가입 또는 로그인합니다.
2. Vercel 서버 API가 Supabase Auth를 통해 인증을 처리합니다.
3. 인증된 사용자의 세션을 확인합니다.
4. 데이터 요청 시 로그인한 사용자의 ID를 기준으로 기록을 조회하거나 저장합니다.
5. 로그아웃하거나 인증되지 않은 경우 데이터 API 접근을 제한합니다.

**보안 및 접근 제어**

- `api/auth.js`: 회원가입, 로그인, 로그아웃, 세션 확인
- `api/state.js`: 사용자별 데이터 조회 및 저장
- `pds_user_state`: 사용자 ID를 기준으로 데이터를 관리하는 테이블
- 서버 환경 변수로 Supabase 연결 설정 관리
- 인증되지 않은 요청에 HTTP 401 응답
- 데이터 수정 요청에 동일 출처 검사 적용
- HttpOnly, SameSite 쿠키 사용 및 운영 환경에서 Secure 속성 적용
- 브라우저에서 Supabase 데이터베이스로 직접 CRUD 요청을 보내지 않고 서버 API를 경유

사용자별 접근 제어는 서버 인증과 데이터베이스의 사용자별 접근 정책을 함께 고려하여 구성합니다.

## 📅 T07 — 5일간 관찰 및 계획 개선

T07에서는 다이어리의 계획, 실행, 돌아보기 기능을 활용하여 **5일간의 기록을 관찰하고 계획 규칙을 개선하는 과정**을 진행했습니다.

주요 활동은 다음과 같습니다.

- 관찰할 질문과 측정 기준 설정
- 5일간 날짜별 실행 및 완료 기록 작성
- 기존 계획의 규칙 변경 및 수정 이력 확인
- 변경 전후 기록 비교
- 기록을 바탕으로 수행 결과 돌아보기

개인별 관찰 내용과 실제 수행 기록은 README에 공개하지 않고, 사용자 계정 내에서 관리합니다.

## 💾 데이터 저장

Supabase PostgreSQL을 사용하여 계획, 할 일, 실행 기록, 돌아보기 데이터를 저장합니다.

T07에서는 사용자별 데이터 테이블인 `pds_user_state`를 사용하며, 로그인한 사용자의 ID를 기준으로 기록을 관리합니다.

브라우저는 Vercel 서버 API를 통해 데이터를 조회하고 저장합니다.

서버 연결에 실패하면 기존 기록을 보호하기 위해 편집 기능을 제한합니다.

## 🚀 사용 방법

1. 배포 사이트에 접속하여 회원가입 또는 로그인합니다.
2. 원하는 날짜를 선택합니다.
3. **새 계획 만들기**에서 계획 제목, 기간, 성공 기준을 작성합니다.
4. 계획에 연결할 할 일을 추가하고 날짜와 우선순위를 설정합니다.
5. 할 일을 수행한 뒤 완료 체크와 실행 기록을 저장합니다.
6. **돌아보기**에서 수행 결과를 확인하고 개선 사항을 작성합니다.
7. 필요한 경우 계획 수정 이력을 확인하거나 전체 기록을 JSON으로 내보냅니다.
